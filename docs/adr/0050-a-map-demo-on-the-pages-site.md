# 0050: A map demo on the Pages site

Status: Accepted by the owner, 13 October 2026 ("Let's go ahead and add it then implement it"). Changes SPEC section 4 (the layout lines for `apps/map-demo` and `apps/site`, and a paragraph on the map demo after the board's) and SPEC's dated line. Amends ADR 0029: the Pages site holds a second page with script, at `/map/`, under the board's rules, and this is the record that ADR 0029's Consequences ask of such a page; the rules ADRs 0029 and 0035 set for tour and guide pages are unchanged. Says when ADR 0038's option C comes due. Section 9 is unchanged. The plan is `docs/plans/map-demo.md`, and the data check is the row of 13 October in `docs/notes/verified.md`.

## Context

`tests/map-page` is a fixture. It is a private canvas page of the Moon with synthetic observations, built for the Playwright specs and ADR 0041's check; it reads nothing from its URL, links through `window.__tabdockMapPage.connect()`, which exists only because the page is never published (ADR 0038, decision 8), takes a wider policy when a test asks, and is served only by a loopback dev server. Its value is that it holds still: the walker, the specs and the copyable check in `tests/ci-check` rest on its tools, ids and bytes.

People need to see what is possible. The demo board at `/` shows pairing, roles, prompts and an image on a toy board. The target scenario (`docs/plans/map-classroom.md`) is a map and a globe that a client drives, captures and follows, and nothing a visitor can open shows that. The owner asked for a minimal public map demo, in this repository, beside the board.

Nothing is on npm yet. 0.1.0 is M5's code, and M6, which carries images, page state and the map profile, ships in the release after it (ADR 0049, decision 3). A page outside this workspace could take the packages only as tarballs, as guide page 23 shows, or wait. The profile itself is `@tabdock/sim-page/map`, private, and ADR 0038 publishes it as a package only once a real map page has used it.

A page on the site shares the board's origin. The relay's allowlist entry for that origin vouches for it (S2), and in one tab it shares the `sessionStorage` where the adapter keeps its records, each keyed by relay URL and page path (`storageKey` in `packages/adapter/src/core.ts`). ADR 0029 keeps tour and guide pages free of script for that reason, and says a page that wants script needs a record of its own.

## Options

A. Polish the fixture and publish it. One page to keep, but publishing means removing its connect hook, replacing the Moon's synthetic records with real ones and taking the board's dial rules, and every change made for presentation would then move CI's fixture, its walker's expectations and the copyable check with it.

B. A new private app here, `apps/map-demo`, built into the site at `/map/`. It runs the profile's own world and tools from `@tabdock/sim-page/map` over Earth, so the demo is the profile in a presentable page; it is bundled from the workspace, so it needs nothing from npm; and CI builds it with the site. It shares the board's origin, so it takes the board's rules for a page with script.

C. A separate starter repository now, with a real map library. The most realistic, and the page ADR 0038's option C waits for, but today it would install tarballs or git paths, bring tiles and fonts from other origins under their own terms, keys and CORS rules, take on WebGL's capture rules, and split review across repositories while the profile can still change.

## Decision

B now, and C once the release after 0.1.0 is on npm: a starter repository with a real map library installs the published adapter and copies the profile, and once it has used the profile and the shapes held, ADR 0038's option C, a published schema package, comes due. The backlog carries that row. The map demo is not that page: with no map library, it cannot show that the shapes hold for one.

The constraints, each held by a test or a build check the plan names:

1. **A private app.** `@tabdock/map-demo`, in the workspace and never published; `apps/site` builds it into `/map/`. `tests/map-page` stays CI's fixture, unchanged, and the demo imports nothing from it.
2. **Earth from public-domain data.** Natural Earth's 110m land and 110m lakes at tag v5.1.2, in the public domain by its terms of use, vendored as one generated module that carries the credit "Made with Natural Earth." A generator under `apps/map-demo/scripts`, run by hand, fetches the two files at that tag, stops if either's SHA-256 differs from the pin it holds, quantizes to 0.1 degree and writes the module; neither CI nor the page ever fetches them. No tile, font, image or style comes from another origin.
3. **A plain canvas, no map library.** A flat map and a globe, drawn with the profile's geometry (`packages/sim-page/src/map/geometry.ts`), so what the tools call in view is what the canvas draws. The drawing depends on the world's state alone, so one view captures to the same bytes.
4. **The profile's tools.** `createMapTools()` over a `MapWorld` of Earth, with every group that world serves (it has no clock), beside `edit_stop` and `reset_edits`, under `MAP_PAGE_POLICY` with `imageTools: ['capture_view']`; proposals stay off and invites at the adapter's default. `capture_view` draws the page's own map again on a canvas of its own, never the tab, which shows the pairing code, and fits it under the relay's cap. The page publishes `MapPageState` on each discrete change (ADR 0040).
5. **A short tour.** One walkthrough of four to six neutral, factual stops, each about something the vendored data draws, and a few observations outlining features in it, credited to Natural Earth and marked as outlines, not photographs. No border, contested name, person, company or brand appears, and no employer's data, branding or imagery (CLAUDE.md's personal-hat rule).
6. **It dials only a relay its visitor chose.** As the board does (ADR 0029 and its notes): `?relay=`, checked by the board's own rules, shows a Connect bar whose button takes only a trusted click once it has held still for half a second in a visible, focused tab, and without `?relay` the page offers a Connect form; the choice is remembered for that tab and relay URL under a key of its own, so a relay chosen on the board never connects the map. Unlike the board it reads no policy from its link and has no test hook in any build: tests click the bar as a person does and approve through the widget with `@tabdock/adapter/testing`. It never links inside a frame. The adapter's widget does pairing and approval.
7. **The board's static rules.** Its `index.html` carries the board's meta policy without `worker-src` (`default-src 'none'`, scripts from its own origin, its one inline style by hash, `connect-src wss: ws:`, `base-uri 'none'`, `form-action 'none'`) and a no-referrer meta, and loads `./main.js` by a relative path. The site build reads `/map/` back and stops unless it holds exactly that page, its script and its source map, under that policy; tour and guide pages keep their rule of no script.
8. **No new runtime dependency.** `@mcp-b/webmcp-polyfill` at exact 5.1.0, which CLAUDE.md allows a demo page, zod, and the workspace's adapter and sim page; esbuild builds it.
9. **A phone.** The page fits 375 CSS pixels with no sideways scroll, and whatever a gesture does, a button does too.

**Size budget.** The vendored geography is at most 24,000 bytes (about 15,500 as measured); `main.js`, minified, at most 800,000 bytes and 200,000 gzipped (the fixture's bundle, minified, measured 679,970 and 171,423 on 13 October); `index.html` at most 16,000 bytes. The source map, which only developer tools fetch, is outside it. A test holds the budget against the static build.

**SPEC wording.** Section 4's layout gains, after the `apps/demo` line: "`apps/map-demo       A map and globe of Earth on a plain canvas, from vendored Natural Earth data, running the map profile's tools; published at /map/ (ADR 0050)`". Its `apps/site` line now reads: "`apps/site           Builds the GitHub Pages site: the demo's static build at /, the map demo's at /map/, docs/tour at /tour/ and docs/guide at /guide/, Mermaid drawn to SVG at build time; kept out of the pnpm workspace, with its own lockfile`". A paragraph follows the board's: "The map demo (ADR 0050) draws Earth from Natural Earth's public-domain 110m land and lakes, vendored as a generated module, as a flat map and a globe on a plain canvas with no map library. It registers the map profile's tools from `@tabdock/sim-page/map` with `edit_stop` and `reset_edits`, under `MAP_PAGE_POLICY` with `capture_view` as its image tool; `capture_view` draws its own map again, never the tab, and the page publishes `MapPageState`. It dials only a relay its visitor chose, by the board's rules for `?relay=`, its Connect bar and its form, under a remembered choice of its own; it reads no policy from its link, has no test hook in any build and never links inside a frame. Its static build carries the board's meta policy without `worker-src`." The dated line reads "last amended 13 October 2026 by ADRs 0038 to 0050 and their notes".

Section 9 stays as it is. S2's check now vouches for two pages of the project's own code on the site's origin, the board and the map demo, both built from this repository under review, and tour and guide pages still carry none. S4 to S6 hold as on the board: the click comes before the adapter starts, the operator approves each client in the widget, and `reset_edits` prompts. The page's call strip names a tool and how it ended, never its arguments, and its tour panel shows a stop's text, which `edit_stop` lets a client set, only as text.

## Consequences

A visitor can open `/map/`, connect a relay of their own and watch their client move a globe, capture what it sees and follow it, with nothing to install. What a visitor needs is what the board needs: a relay that admits the site's origin, which on their own machine means `TABDOCK_ALLOWED_ORIGINS` and the browser's permission for a public site to reach a loopback address, so the page says so beside its form. The site now has two pages with script, and a fault in either can read the other's `sessionStorage` in the same tab; the adapter's records are keyed by page path and each page's remembered choice is its own, but neither page is a boundary against the other. The renderer, the capture's fit loop and the gestures follow the fixture's but are not shared with it, so a fix to one may be owed to the other; a later change may move what stays identical into `@tabdock/sim-page/map`. The vendored data changes only when someone runs the generator, and its pins make a changed upstream file stop the run rather than slip in. The threat model's B10 row and the site's checks and tests grow to cover `/map/`.

## Notes from the map demo's review (13 October 2026)

A security and a newcomer's review of the built page found these departures from the Decision; each is fixed with a test, and these notes replace the sentences above that they contradict. Section 9 is unchanged.

**One lake carries every name in use.** Natural Earth names a lake Lake Malawi, which Tanzania calls Lake Nyasa and Mozambique Lago Niassa, a naming tied to a boundary dispute, so the page broke decision 5 by showing one of them. `src/earth.ts` now shows "Lake Malawi (Lake Nyasa, Lago Niassa)" on the canvas and in every tool result, and keeps the data's id, `lake-malawi`, as a key. The generated module stays a pure rerun of the generator, and `src/earth.test.ts` lists all 26 names, so a regenerated module cannot add an unreviewed one. Decision 5 reads, for a name that differs by the country on its shore: the page names it with every name in use and takes no side. The owner may still choose Natural Earth's name alone or no label (`docs/checklists/map-demo.md`, step 5); either is recorded here.

**`worker-src 'none'`, not no `worker-src`.** Without the directive a worker falls back to `script-src 'self'`, so a script already on the page could start any of the site's scripts as a worker or register one as a service worker, which the board's `blob:` alone refuses. Decision 7 and SPEC section 4's map paragraph now read: the board's meta policy with `worker-src 'none'` in place of the board's `blob:` worker. `mapDemoPolicy` writes it, the site's read-back (`scriptedPolicy(hash, false)`) expects it, and `tests/e2e/specs/map-demo.spec.ts` sees a same-origin worker, a blob worker and a service worker each refused by `worker-src`. The threat model's B10 row and the READMEs say the same.

**The read-back reads every URL attribute.** It followed only `href` and `src`, and only the first in a tag, so a `srcset`, `poster`, `formaction` or `ping` pointing elsewhere passed it while the policy alone stopped the load. `urlsIn` in `apps/site/lib/checks.ts` now reads each start tag's attributes past any `>` in a quoted value and checks `href`, `src`, `poster`, `data`, `action`, `formaction`, `background`, `cite`, `longdesc`, `manifest` and `xlink:href`, each `srcset` and `imagesrcset` candidate and each `ping` target, so decision 7's read-back is the second opinion it claims to be.

**Every gesture has a button or a key.** Constraint 9 said a button does whatever a gesture does, but nothing but a drag panned, and the canvas took no focus. The map now sits in the tab order (`tabindex="0"`, `role="application"`, labelled for a screen reader); on it the arrow keys pan by an eighth of its width and plus and minus zoom by a button's step (`keyAction` in `src/gestures.ts`). Constraint 9 reads: the page fits 375 CSS pixels with no sideways scroll; zoom, projection and the tour each have a button, and panning is a drag, a touch or the arrow keys. A plain wheel now scrolls the page past the map, and Ctrl or Cmd with it, which is how a trackpad pinch arrives, zooms the map (`wheelZoom`), so a desktop visitor can scroll to the tour card.

**Smaller than measured.** The script carried every one of zod's message languages, about 260 KB minified, because the map profile imports classic zod, whose namespace re-exports them all. `englishOnlyZod`, an esbuild plugin beside the board's build in `apps/demo/scripts/server.ts`, leaves all but English out of both pages, with every message unchanged: the map's `main.js` measured 447,415 bytes and 148,280 gzipped on 13 October with this review's other changes in, against 707,027 and 185,858 before, and the board's 741,640 against 1,087,634. The budget is unchanged; `test/server.test.ts` also holds the map's script near its measured size and free of other languages, so the languages coming back fails a test before the budget would.

**The page around the map.** On a screen 1,100 pixels or wider the column leaves the widget's panel a lane, so a client's tour is never drawn under it; on a phone a line, shown once a relay is chosen, says to fold it. The tour card says so when the map has left the current stop, since the world keeps the last stop it went to (the profile's rule, unchanged). `capture_view` draws a fifth narrower each try rather than half, and draws names up to twice as large on a narrower picture. A chosen relay that has not linked after ten seconds gets a status line naming what to check. The fixture's fit loop and wheel are unchanged, as decision 1 keeps it.

**The recording.** `pnpm record:map-demo`, which the plan names, films the static build by hand into `apps/map-demo/recording/`, which git ignores; it closes its throwaway relay before writing, so any code it filmed is dead. A video of Claude itself stays the owner's step in `docs/checklists/map-demo.md`.

## Notes from the recording (13 October 2026)

**The recording is kept, and `/map/` serves it.** The owner asked for a short recording that shows what is possible, shown on the page and in the README. `pnpm record:map-demo` (`tests/e2e/src/record-map-demo.ts`, by hand and never in CI) now runs `pnpm relay` in local mode with a throwaway `TABDOCK_HOME` whose `TABDOCK_ALLOWED_ORIGINS` names the static host, clicks Connect and Allow as driver as a person does, and has an MCP SDK client take the tour as Claude would, under a caption bar naming each step. No frame shows the pairing code or its QR code: a shade covers the widget's lane before the click, the code's block is hidden inside the widget before the shade lifts, and each scene checks that neither has a box on screen, stopping the run if one has. The run prints no code or token, and the relay is gone before a file is written. It writes the take, its poster and a still of each scene into the ignored `apps/map-demo/recording/` for review, and copies a take within budget into `apps/map-demo/media/`, which is tracked. This replaces the earlier note's recording paragraph, which kept every file out of the repository.

Decision 7's read-back now reads: the site build reads `/map/` back and stops unless it holds exactly that page, its script, its source map and a `media/` directory of exactly `poster.png`, a PNG of at most 300,000 bytes, and `map-demo.webm`, a WebM of at most 4,000,000, each judged by its first bytes, and unless the page links both (`MAP_DEMO_MEDIA` in `apps/site/lib/checks.ts`). `buildMapDemo` copies them from `apps/map-demo/media/` and stops if either is missing, and the dev server serves them by those two names alone. The page shows the poster, loaded lazily under its unchanged `img-src 'self'`, as a link to the video, which the browser plays on its own. The poster is a picture of the page itself, so nothing comes from another origin. Over budget means a shorter take, never a raise. Section 9 is unchanged: S11 holds for the recording as for a log, since no frame shows a code and nothing the run prints holds one.

**The README links the site by its fallback name.** The custom domain is the owner's to name, so the README shows the poster as a link to `https://paulmramirez.github.io/tabdock/map/`. GitHub Pages answers a project site's `github.io` path with a redirect to the custom domain, path kept, once one is set (`docs/notes/verified.md`, 13 October 2026); until the site is published the link answers 404.
