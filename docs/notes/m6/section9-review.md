# M6 section 9 review (A6.28)

The review of SPEC section 9 (S1 to S14) across M6, run on 12 October 2026 against `m6` at `67d9f44`, after Wave 3's cross review, with ADRs 0038 to 0048, `docs/threat-model.md` and `docs/plans/M6.md` as what was decided. It confirmed fourteen findings and refuted five. None was high: three were reported as medium and each verified as low, and the other eleven were low as reported. Every confirmed finding was fixed in one round on two branches, `m6-sec9-relay` (`6cdd767`) and `m6-sec9-page` (`fc475a4`), merged into `m6` as `d352e59` and `539349d`. So A6.28 holds: no high-severity issue is left unaddressed.

## Method

Eight reviewers each took one area: agent tokens and `/g/mcp`; proposals; the members file and sessions; the restart snapshot; images, page state and labels; resource bounds; secrets in logs, files and output; and the adapter, widget and page-side checks. Each read its code and decisions against S1 to S14 and ran probes against the real relay and the real adapter core from scratch vitest configs outside the repository, editing nothing in it. Each finding then went to skeptics of its own, separate agents told to refute it: a finding counted only when a skeptic reproduced it on the real code, an unreproduced one was refuted by default, and the skeptics set the severity that stands. The confirmed findings were fixed in one round by two fixers in parallel worktrees, one on the relay and one on the page side and the documents. Each fix carries a test that fails on the old code or on a mutant with the fix removed; a fix to the documents alone is held by a doc test that fails on the old wording, beside a test pinning the behaviour it describes. Nothing was skipped or loosened.

## What each area found sound

**Agent tokens and `/g/mcp`.** Minting draws 32 bytes from `crypto.getRandomValues`, and the relay, the adapter's storage and the snapshot keep only the SHA-256; the token reaches no log, audit record or URL. Every mint refusal holds, from no public URL to the page's grant budget. `/g/mcp` checks Host, then Origin, then local-only before the bearer is read, and every miss is one JSON 404 with no challenge; the token is asked about again after the body. No token is approved in advance (probed under `autoApprove: 'observer'`), and every close path ends the attachment, the waiting prompt, MCP sessions and listen streams, a listen opened as the token closes included (5 of 5 rounds). An agent pairs only through its own token, reaches only its page, never proposes, and counts as an invitee for every budget.

**Proposals.** The adapter's bind runs an observer's write only for its own accepted record, same caller, tool and canonical arguments, once, within 60 s, so a hostile relay can at most run the exact accepted call once. Accept is armed and trusted only. The relay checks again after the argument worker, at a run's start and at dispatch; a revoke settles pending, queued and running proposals; S13's identical `proposal_not_found` answer holds; and every charge was traced through reserve, commit, keep, forget and release. A run's result reaches its proposer only as labelled text.

**Members file and sessions.** The member list's ended set is right for removed, added, moved and swapped ids, and a change reaches attachments, requests, sponsored invites and tokens, proposals, `/pair` sign-ins, MCP sessions and listen streams, with the sign-in race closed by a generation check after the body. The file loader holds its caps, refuses non-UTF-8 text and duplicates, names a line by number only, checks mode and owner on the file, its ancestors and any link's directory, and cannot be stalled by a FIFO. Sessions only narrow, demote newest drivers first, end on either clock with a late timer letting nobody past, and cap invites and their attachments at the end.

**Restart snapshot.** The loader takes only a regular 0600 file it owns with one link, unlinks it before deciding, checks the audit digest before parsing, then the version, age, mode and `/pair` credentials digest. No replay, failed start or rollback restores a revoked grant, since each welcome rotates the resume token. The stop path drops work while closing and writes `snapshot_written` and `relay_stop` with nothing awaited between them. Members are rebound to their subjects at load, sponsors' invites, attachments and tokens end with them, the fit checks count as the hub counts, and the file holds digests only.

**Images, page state and labels.** `parseImageEnvelope` and `checkImage` take only PNG, JPEG or WebP in exact lower case, canonical base64 checked by length before one strict decode, matching first bytes and header dimensions within the caps; the relay checks again, only for a tool the hello declared, keeps type, size and SHA-256 in the audit, and puts the image behind the label with no `structuredContent`. Page state passes its frame budgets before both size caps, is charged against `TABDOCK_MAX_STATE_BYTES`, is spliced after its header with line separators escaped, and is read only through `#access`; waits hold their slots and charges and release them in a `finally`.

**Resource bounds.** Waits, page state, proposals, images, the watchers' share, seats, agent tokens, the members file and the snapshot each hold their caps, and every count map deletes its key at zero. A churn probe of 200 page sessions through state waits and proposals left the heap 1,423 bytes a cycle lower, against 4,583 higher without M6's steps, and six waiting 2 MiB calls held no retained buffer on `/mcp` or `/g/mcp`.

**Secrets in logs, files and output.** The redacting logger and every log call in the relay's M6 code keep tokens, secrets and emails out; the M6 audit records are strict; members file refusals never quote a line or the path (11 malformed files and one at mode 666 probed with sentinels); the session record and snapshot hold no secret. A whole lesson with a restart at debug level left none of 28 secrets in 70 log lines, 26 audit lines or the snapshot. `demo:m6` masks codes, links and the agent token and scans what it prints.

**Adapter, widget and page-side checks.** `callerRole`, `pageRole` and `grantedRole` take the least of the page's grant, the roster and the invoke, cap invite and agent grants and enforce a session's seats; `check()` runs again after the prompt and the image gate. Prompts deny on timeout, and a client confirmation counts only under the page's own rule. The widget sets text only through the `textContent` setter taken at mount, isolates names and arguments, arms Accept and Revoke, and draws only a canonical invite URL in its QR. The adapter's M6 suites passed (107 cases), and the testing, record and Markdown suites (79).

## Refuted findings

Each of the five was reported as low.

**A page clock running ahead stretches a token past its lifetime** (agents). The relay's record does run longer, but the adapter caps each prompt at the relay's own `expiresAt` on the page's clock, so on a page more than the 60 s prompt lifetime ahead the prompt times out before it is shown, three such burn the token, and no attachment is ever made (a probe of the real relay and adapter core, 3 of 3 cases).

**A refused snapshot leaves no audit record** (snapshot). It reproduces, but S7, ADR 0046's Decision and B7 name only `snapshot_written` and `snapshot_loaded`, and the start warns with a fixed reason on stderr; not a defect against any requirement.

**`pnpm ci-check`'s scan misses a code in other forms** (secrets). The scan matches only the display form, but every source of a code in the scanned output gives that form or none: the relay issues only it, the test process passes it on unchanged, and the normalised form exists only inside the relay's matching, where it is hashed (none of 100,000 issued codes missed).

**New link mints under invites `'off'`** (adapter). `renewSessionLink` lacks the local check `invite()` has, but the relay refuses the frame as policy, so no invite is minted, shown or redeemable (probed through a reload into `'off'`).

**Animated WebP and APNG pass the dimension check** (content). Refuted by default: the skeptic's run stopped before its probe ran, and it said itself that this is no evidence the defect is absent. Its reading stands, and a probe for this note confirms it: `checkImage` reads only the PNG IHDR and the WebP canvas, so it accepts a PNG whose `acTL` declares 1,400 frames on a 4,096 square canvas. The relay never decodes pixels and the size cap still bounds the bytes, so the relay's memory is not at stake; what a client spends decoding such an image is. S9 and B11 bound header dimensions, which hold as written, so this is not a breach of a stated requirement, but it is left open for the owner rather than closed.

## Merge and checks

The two branches conflicted only in documents: ADR 0044's notes from both fixers now sit in one section, and threat model rows B11 and B13 take the page side's text and B12 the relay side's. After the merge two tests failed, and each was fixed at its cause with nothing loosened. `doc-style.test.ts` found guide page 20 at 1,323 words against its 1,300, both rounds having added a sentence; the page was trimmed with no rule dropped (`5cf3163`). And the A6.20 room test in `response-stalls.test.ts` read two of guest-1's ceiling lines where it expects one: the repeated-lines window is the wall clock's minute, so a run that straddles a minute's end rightly writes the line again. Moving the clock on a minute after the first line gave exactly the failure seen, and starting the test 600 ms before a minute's end failed it 3 times in 3; each real-socket test in that file now starts with at least 15 s left in its window, and the same 600 ms start passes 3 times in 3 (`14a3be1`). On the merged branch with both fixes, `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck`, `pnpm test` (3,133 passed, 2 skipped, in 201 files), `pnpm test:e2e` (145 passed) and `pnpm demo:m6` (44 s) pass. The script-tag build measures 194,260 bytes, 336 more than after the cross review for the fixes in `core.ts` and `widget.ts`, under the 200,000 ceiling, and the record's modules 12,743 of 13,000, measured with `packages/adapter/scripts/script-tag-build.ts`.
