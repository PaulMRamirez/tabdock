Every check here was made on 2 October 2026 against primary sources: documentation fetched directly, npm registry metadata (`npm view`), package tarballs read after `npm pack`, and live probes. WebMCP was probed in headless Chrome for Testing 153, 154 (today's Stable), 155 and 156 with `--enable-features=WebMCPTesting`; MCP-B and the MCP SDKs ran on Node 22.22.0; Claude Code was 2.1.287. A second, independent agent re-checked each claimed discrepancy, and "differs" means that re-check upheld it. Shapes the code depends on are measured in `baseline.md` beside this file.

## Consequences for the build

M0 applied the scaffold fixes (Node 22.18, `allowBuilds`) and pinned every MCP-B reference to exactly 5.1.0. The owner accepted ADRs 0001 to 0006 on 2 October: the adapter detects the `executeTool` input form per page, parses string schemas and treats results as text (0001); consequential tools follow option C (0002); SPEC section 3 was refreshed from this file (0004); `pair_page` waits 50 s (0005); and a minimal OAuth plugin moves into M3 because request-header connectors are missing on the owner's account (0006).

M1 built the relay on the v2 SDK at 2.3.0 with the node adapter at 2.1.1, mounting `createMcpHandler` on `node:http`. `/mcp` checks `Host` but not `Origin`, since hosted Claude sends none; S1 and S2 apply to `/page`. Still ahead: per-client attribution for 2025-era clients and cancellation through the SDK's sessionful route (M2), whether hosted Claude refreshes a changing tool list and whether an uncontested Web Lock keeps a tab from freezing (M3), and the `list_changed` plan for M5, since 2026-07-28 sends it only over `subscriptions/listen` and hosted Claude documents none of it.
