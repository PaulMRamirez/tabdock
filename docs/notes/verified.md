## Consequences for the build

M0 applied the scaffold fixes (Node 22.18, `allowBuilds`) and pinned every MCP-B reference to exactly 5.1.0. The owner accepted ADRs 0001 to 0006 on 2 October: the adapter detects the `executeTool` input form per page, parses string schemas and treats results as text (0001); consequential tools follow option C (0002); SPEC section 3 was refreshed from this file (0004); `pair_page` waits 50 s (0005); and a minimal OAuth plugin moves into M3 because request-header connectors are missing on the owner's account (0006).

M1 built the relay on the v2 SDK at 2.3.0 with the node adapter at 2.1.1, mounting `createMcpHandler` on `node:http`. `/mcp` checks `Host` but not `Origin`, since hosted Claude sends none; S1 and S2 apply to `/page`. Still ahead: whether hosted Claude refreshes a changing tool list and whether an uncontested Web Lock keeps a tab from freezing (M3), and the `list_changed` plan for M5, since 2026-07-28 sends it only over `subscriptions/listen` and hosted Claude documents none of it.

M2 added the SDK's documented sessionful route for 2025-era clients beside the stateless 2026-07-28 leg, bound each session to the user who opened it (the SDK does not), and wired client cancellation through on both legs (ADR 0009). The argument check uses the SDK's bundled CfWorker validator over a copy of the page's schema without regexes, `format` or `uniqueItems`, on a worker thread with a time limit, because the validator's cost can grow exponentially with the schema and quadratically with the arguments (ADRs 0008 and 0010). The MCP-B polyfill cannot stop a running handler, so the page holds its write slot until the handler ends, or, if the page unregisters that tool mid-run, until the call's deadline plus 2 s (ADR 0001's notes, ADR 0012). Claude Code 2.1.288 still speaks 2026-07-28 and is named in the page's roster and activity log (`check:claude-code:m2`, 3 October). One approval covers one page (ADR 0011), and the M2 limits added two close codes (ADR 0012).

M3 checks tokens with `jose` behind the SDK's `verifyBearerToken`, since the SDK ships no verifier, and signs the phone in at `/pair` with `openid-client`; the SDK's authorization-server helpers stay out because they are deprecated and tied to Express (ADR 0013). WorkOS AuthKit, with CIMD and dynamic registration on and a default Resource Indicator, is the provider, and ngrok's free static domain is the tunnel, since a Cloudflare quick tunnel drops streamed responses (ADR 0014). Claude Code 2.1.288 signs in through CIMD (`check:claude-code:m3`, 3 October). The widget draws its QR code as one SVG path built with DOM calls and zod runs jitless, so pages under Trusted Types work. Holding a Web Lock keeps a tab from freezing but not from a Memory Saver discard, and whether hosted Claude sees a changed tool list mid-chat is still measured by hand (`docs/notes/spike.md`).
