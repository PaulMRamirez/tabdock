# Where the relay runs from M4

Research for the M4 plan, 3 October 2026. Every fact was fetched today from vendor docs, pricing pages or a live probe. Confidence: H (primary source or probe), M (vendor article, staff forum answer, or my arithmetic), L (unverified). Nothing was signed up for or deployed.

## Recommendation

**Fly.io: one `shared-cpu-1x` 512 MB Machine in `iad` with a 1 GB volume, behind the owner's own subdomain, about $3.84 a month.** It is the cheapest option that meets every need and the only one whose client address header was checked by a live probe: Fly's proxy replaced a forged `Fly-Client-IP` with the real peer. A mounted volume makes Fly create exactly one Machine and refuse the deploy strategies that run two at once, so the in-memory store never splits. No request time cap is documented, only an idle timer the relay's 15 s keepalives beat. Deploys run in GitHub Actions with a token made in Fly's dashboard, so the owner can set up from a phone browser and this sandbox can start a deploy through the repo-scoped GitHub API without holding a Fly credential.

**Fallback: Render, Starter plus a 1 GB disk, about $7.25 a month.** Fully dashboard-driven with native GitHub deploys, 100-minute requests, no WebSocket maximum, and Render's own article says Cloudflare overwrites `CF-Connecting-IP` (not probed). Railway ($5) is close but caps HTTP streams at 15 minutes and documents no anti-spoofing guarantee for `X-Real-IP`.

On any host, point a DNS-only (not proxied) subdomain of a domain the owner controls at the platform, so the Claude connector URL survives a later move.

## Relay facts that bind any host

Idle RSS of `node src/main.ts` measured 137 MB today, so 512 MB is the floor (H). Pings and SSE keepalives every 15 s (`packages/relay/src/config.ts:197`, `packages/protocol/src/constants.ts`) beat any idle timer of 60 s or more. The relay binds loopback only (`config.ts:402-405`) and in public mode refuses `/page` upgrades carrying `Forwarded` or `X-Forwarded-*` (`relay.ts:88-94`). On a platform TLS ends at the edge and the container listens on all interfaces, so M4 needs an ADR amending S12 and SPEC section 2's relay-trust line, and one configured header (`Fly-Client-IP`) trusted for addresses. Fly's health checks arrive by private address, so the health route must sit outside the strict Host allowlist.

Every restart loses the in-memory store on every platform: pages reconnect within the 0.5 to 30 s backoff but are not resumed; attachments, pairing tickets and (from M4) invite hashes vanish; 2025-era MCP sessions end. OAuth tokens stay valid, since verification is stateless. Deploy on demand, not on every merge.

HTTPS reached every platform API (api.fly.io, api.machines.dev, registry.fly.io, backboard.railway.com, api.render.com, run.googleapis.com, app.koyeb.com, api.digitalocean.com, api.hetzner.cloud) and arbitrary hosts (H). The `flyctl` 0.4.111 download from GitHub releases returns 403, the proxy refuses WebSocket upgrades (`/root/.ccr/README.md`), the Docker CLI has no daemon running, and no platform credentials exist (H). The GitHub API is repo-scoped (`repos/PaulMRamirez/tabdock` 200, global paths 403), so the route is: push a branch, dispatch the deploy workflow, then curl the live 401 challenge and metadata. Dispatch was not tried (M). The live `/page` WebSocket stays on the owner's checklist.
