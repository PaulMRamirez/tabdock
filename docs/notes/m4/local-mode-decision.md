# Owner decision: local mode by default (3 October 2026)

After decisions D1 to D6, the owner asked for a zero-config, batteries-included local relay "so that we don't dictate how users set this type of infrastructure up themselves and to reduce complexity". It runs as `pnpm relay` now, and as `npx @tabdock/relay` from the 0.1.0 release in M5, with no `.env`, no accounts, no tunnel and no host; it binds 127.0.0.1 and allows localhost page origins. Auth is an owner token generated on first run and saved to a private file outside the repo (mode 0600, in a per-user configuration directory), never printed or logged; the `claude mcp add` command the relay prints reads it from that file. One named user, "you", keeps approvals, roles, revoke and the audit log working, as ADR 0016 requires: no account, never no identity.

Everything else is opt-in and provider-agnostic: a public URL behind any tunnel, any standards OIDC provider with client ID metadata documents or dynamic registration, any container host. Fly.io, WorkOS and ngrok become the documented reference deployment, not a requirement. The limit is stated plainly: a local relay serves only clients on the same machine (Claude Code and other local MCP clients), while Claude on the web, desktop and mobile connects from Anthropic's cloud and needs the public layer. The decision lands as ADR 0022, "local mode by default", and as the first workstream of M4, with the hosted pieces framed as the reference deployment.

Later on 3 October the owner answered the plan's questions: accept ADRs 0017 to 0022 and start M4 ("Accept all, start M4"), and accept ADR 0019's narrowing of S7, under which refusals past 10 lines a minute per user and 30 relay-wide become per-minute summaries, while calls that reach a page are always logged in full. The ADRs land as Proposed and a separate commit marks them accepted, as with ADR 0012.
