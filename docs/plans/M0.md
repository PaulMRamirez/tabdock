# M0 plan: scaffold and baseline

Goal: a pnpm workspace that typechecks, lints and tests from a clean clone, a demo page whose six tools are registered through the MCP-B polyfill, and a measured baseline of how MCP-B's own local relay exposes that page to an MCP client. Nothing Tabdock-specific runs yet; M0 exists so that M1 starts from known shapes instead of guesses.

## Order of work

First, re-verify every moving fact in SPEC section 3 (WebMCP, MCP-B packages, MCP SDK, Claude and Claude Code docs, tool versions) and log it with today's date in `docs/notes/verified.md`. Any disagreement with the spec is raised in the milestone report and, where it changes a decision, recorded as an ADR.

Second, scaffold the layout from SPEC section 4: `packages/protocol`, `packages/relay`, `packages/adapter`, `packages/sim-page`, `apps/demo`, `tests/e2e` and `docs/`. Each package gets strict TypeScript, ESM output and a README stating its role and the milestone that fills it in. The root holds the shared tsconfig, ESLint flat config, Prettier, Vitest projects, `.env.example`, `LICENSE`, `NOTICE` and a GitHub Actions workflow that runs install, lint, typecheck, unit tests and the browser tests.

Third, build `apps/demo`: a canvas board with items and a viewport, state held in a pure model module so it can be unit tested in Node, and six tools registered through the polyfill (`get_view`, `list_items` read-only; `add_item`, `move_view`, `highlight_item` mutating; `clear_board` consequential). The page renders every change so a watcher can see what an agent did.

Fourth, the baseline. Serve the demo page, load it in headless Chromium through Playwright, start MCP-B's local relay, and drive it with an MCP client built on the official SDK: list the tools and call each one. This scripts as much of A0.2 as the sandbox allows; the step that needs Claude Code on the owner's laptop goes into `docs/checklists/M0.md`. A second script measures, in the page, the real shapes returned by `getTools` and `executeTool` (success, handler error, abort) and the delay between a registration change and the `toolchange` event, and writes them into `docs/notes/baseline.md` (A0.3).

## Commands

`pnpm install`, `pnpm lint`, `pnpm typecheck` and `pnpm test` must pass without a browser. `pnpm test:e2e` runs the Playwright tests and needs Chromium (`pnpm exec playwright install chromium` on a laptop; the cloud sandbox already has one). `pnpm dev` serves the demo page; the Tabdock relay joins it in M1. `pnpm demo:m0` builds the demo and runs the scripted baseline end to end, printing each MCP request and result.

## Done when

A0.1 passes from a fresh clone, the scripted part of A0.2 passes and its manual remainder is in the checklist, A0.3's notes hold measured values, the explainer `docs/tour/00-baseline.md` exists, a reviewer agent has checked the work against SPEC section 9 (most requirements do not apply yet; the review confirms nothing in M0 contradicts them), and one pull request carries the milestone.
