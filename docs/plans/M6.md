# M6 plan: classroom on one tab

Goal: a map and globe page a teacher projects can be driven, followed and reviewed by a room. A shared map and globe tool profile runs on the sim page and on a canvas test page (A6.1, A6.2); declared image results reach clients behind their label, are refused whole when malformed and are audited (A6.3 to A6.5); clients read and wait on state a page publishes, and a frozen tab recovers (A6.6, A6.7); CI checks a page in local mode with no secret, beside an advisory walk (A6.8, A6.9); observers propose writes that run only when the operator accepts (A6.10 to A6.13); a members file reloads without a restart, and time-boxed sessions narrow the policy and end what they let in (A6.14 to A6.17); a graceful restart may resume from a snapshot bound to the audit chain (A6.18); 40 watchers fit beside the members' seats under a response ceiling and a watching share, with agent tokens for unattended clients (A6.19 to A6.24); the operator saves a session record that `audit --match` holds to the log (A6.25); the integration holds the size ceiling, the phone layout and the MCP-B 6.0.0 leg (A6.26); the owner's devices cover what the sandbox cannot reach (A6.27); and a separate agent's section 9 review leaves no high-severity issue open (A6.28). ADRs 0038 to 0045, proposed on 9 October, were accepted on 10 October under the owner's standing instruction to take the recommendation where a question is open and record it; ADRs 0046 to 0048 are new. Each ADR's Decisions section records the settled questions in full, and `docs/notes/verified.md` the facts, each dated.

## Decisions in brief

D1 (ADR 0038, map and globe tools): fourteen snake case tools with no prefix, a core of get_view and set_view and six optional groups, each registered whole or not at all; one view shape for maps and globes; features_in_view capped at 200 with no cursor; footprints of at most 1,000 positions; writes resolve with the state they produced, and refusals throw, ending as tool_error. The profile lives in `packages/sim-page/src/map/` as `@tabdock/sim-page/map`, with zod 4.6.5 schemas; the relay and adapter never read profile names. The private canvas page, `tests/map-page`, adds edit_stop and reset_edits (its only consequential tool) for 16 tools, dials only on a trusted click or its connect hook, never from its URL, and publishes its view, clock, walkthrough stop and observation on discrete changes. Guide page 16 documents it.

D2 (ADR 0039, image results): a tool the hello's `policy.imageTools` names may return one envelope `{ image: { mimeType?, data }, text? }` holding exactly one PNG, JPEG or WebP, at most TABDOCK_MAX_IMAGE_BYTES decoded (65,536 by default, 524,288 at most, 0 for none) and 8,192 pixels a side. One strict `checkImage` in `packages/protocol` serves adapter and relay, since the SDK passes malformed base64 that its client then fails whole, label included. Nobody re-encodes. The answer is one text block (the label, the relay's image line and at most 2,000 characters of page text) and then the image, never structured content; an undeclared tool's envelope stays text. The adapter runs one image call at a time, 250 ms apart, with 8 waiting, and the audit records each image's type, size and SHA-256. The demo gains capture_board.

D3 (ADR 0040, page state): fixed tools get_page_state and wait_for_page_state. A page publishes a JSON object or null through `publishState`, which never throws, or a script-tag page through a `tabdock:state` event: at most 16,384 bytes, at most two frames a second, the latest value only, versioned per page session. A wait answers within its timeout (at most 40 s) with the body and `changed`; a user holds two waits across pages and both waiting tools, a page usersPerPage plus observersPerPage, each holding its request charge. Past its frame budgets a socket closes with 1008, an oversized value with 1009, and past TABDOCK_MAX_STATE_BYTES (4 MiB) values are withheld. Reads never move idle expiry, answer page_asleep while asleep and stay out of the activity log and the record. MCP resources wait in the backlog.

D4 (ADR 0041, checking a page from CI): no Claude Code job runs in this repository's CI; the advisory walk is a Playwright project run by hand. The deterministic check uses `@tabdock/adapter/testing`, which reads only the widget's closed shadow root over a structural DevTools session (so Playwright is no dependency), checks replies with `@tabdock/protocol/devtools`, matches a prompt by client name or request id and throws when two match, clicks only an armed button a hit test confirms, and never prints a code. The example is the private `tests/ci-check`, with one walker and one `connectPage()` for a copier to change, run here by `pnpm ci-check` within the default rates, with TABDOCK_HOME under the runner's temporary directory and the audit chain verified at the end. Guide page 17.

D5 (ADR 0042, proposals): under a policy's `proposals` of 'members' or 'all', an observer's write by either route answers proposed with an id instead of role_denied; 'off', the default, keeps role_denied, invitees propose only under 'all', and agents never. The page gets a proposal frame, not an invoke. The operator's armed Accept is that call's confirmation; the relay queues accepted runs in acceptance order, and the adapter runs one only against its own single-use record of caller, tool and canonical arguments, within 60 s. get_proposal and withdraw_proposal make nine fixed tools, and the new proposal_not_found answers an unknown id and another user's alike. Caps: 3 pending per user, 20 per page, 16 KiB and 1,000 values of arguments, and TABDOCK_MAX_PROPOSAL_BYTES relay-wide; outcomes are kept 10 minutes.

D6 (ADR 0043, sessions and members): TABDOCK_MEMBERS_FILE, in public URL mode in place of TABDOCK_OAUTH_USERS, lists up to 500 `sub=userId:Display Name` lines, polled with `stat` every 2 s (no `fs.watch`, no SIGHUP); a bad file keeps the last list, refusals name line numbers only, and a removed member or changed id loses everything held under the old id at once. A time-boxed session, from the widget or `dock.startSession()`, runs 30 to 240 minutes, extends only by the operator, and sets only maxDrivers and proposals, never wider than `attach()`'s ceiling in either layer. It ends on the relay's clock and on the adapter's own, closing every invite-made attachment, live invite and agent token on the page; its watch invites show one QR at a time. In local mode a session is a time box only.

D7 (ADR 0044, larger read-only rooms): TABDOCK_MAX_OBSERVERS_PER_PAGE (40; 0 restores M5) seats invitee observers apart from the people limit, which alone keeps two member seats. TABDOCK_MAX_USERS_PER_PAGE is capped at 50, TABDOCK_MAX_INVITEE_SESSIONS becomes a setting (100, was 50), and TABDOCK_MAX_RESPONSE_BYTES (96 MiB) caps unread answers relay-wide, cutting strangers' first, then guests', never a member's. Watchers share 120 calls a minute per page, 30 per user and 4 in flight, and the roster's Watching section collapses past 8 rows. Agent tokens (TABDOCK_AGENT_TOKENS, off, needing invites and a public URL) live 1, 4 or 8 h, at most 10 per page, kept as digests; the first `/g/mcp` request raises an ordinary prompt, a deny or three timeouts burn the token, it reads one page as observer, and every miss is 404. Google sign-in goes only behind WorkOS. The defaults are provisional until measured.

D8 (ADR 0045, session record): the adapter keeps in memory a record of the calls it accepted, attachments, roles, proposals and where each call was confirmed, capped at 5,000 calls with drops counted, naming people by short ids and never holding arguments, results, images or secrets. It keeps current, previous and ended slots; a session's end offers the record and never saves it unasked, and saving writes JSON and a Markdown summary from an armed box after a warning naming everyone in it. A recorder fault never changes a call. The relay's one change is the audit call record's `callId`, present exactly when the invoke went out, which `audit --match` uses; AUDIT_VERSION stays 1 while 0.1.0 is unpublished. Its modules stay under 13,000 bytes (decision 23, raised from 7,000 on 11 October because built in full they measure 12,375).

D9 (ADR 0046, new, restart snapshot): TABDOCK_RESTART_SNAPSHOT is off by default and needs an audit directory, since `docs/deploy.md`'s rotation relies on a restart ending everything. A graceful stop writes one snapshot at mode 0600, holding hashes and never secrets, and a `snapshot_written` record with its SHA-256. A start loads it only when under 10 minutes old and when the log's last two records are that `snapshot_written` and `relay_stop`, unlinks it before applying it, and drops users no longer valid.

D10 (ADR 0047, new, SPEC section 3 and MCP-B 6.0.0): section 3 is refreshed for M6. MCP-B 6.0.0 has been `latest` since 8 October, so `tests/mcpb6` moves from the beta to exact 6.0.0, calling `installWebMCP()` because an ESM import no longer installs the polyfill; the demo and the map page stay at exact 5.1.0. Chrome Stable is 155. The WebMCP draft of 9 October serializes results as JSON and Chrome does not, which ADR 0001's rule and the image unwrap both cover. The connector docs list image results as supported.

D11 (ADR 0048, new, script-tag ceiling): the ceiling rises from 150,000 to 200,000 bytes. The build measured 134,155 on 10 October at `6ab8389`, and the six adapter-side ADRs need about 40,000 more. The checkpoints below hold each wave to a share, and the session record keeps its own budget, 13,000 bytes by ADR 0045's decision 23 as raised on 11 October under the owner's standing instruction (it was 7,000).

Section 9 changes: S4 (an agent token's first request prompts and is never approved in advance), S5 (an observer's write runs only as a proposal the adapter's own record shows accepted, and a session only narrows the policy), S6 (Accept is that call's confirmation; under deny a consequential proposal is refused), S7 (the call record's new fields, and records for proposals, sessions, member reloads, the snapshot and agent tokens), S8 (waits and proposals end on revoke and on a member's removal), S9 (every new limit, and relay-wide caps that never cut a member's answer), S10 (images, state and proposal results only behind labels, never structured), S11 (agent tokens only as digests, no secret in the members file or the record), S13 (proposal ids are names, never capabilities) and S14 (the observer allowance, invites ending by a session's end, and revoke and the sponsor rule over agent tokens). None weakens a requirement: watchers can no longer take people seats, so members' seats are better protected than before, and the A6.28 reviewer verifies `/g/mcp`, the proposal bind, the members diff and the snapshot loader adversarially.

New dev dependencies, accepted under the standing instruction and named in the pull request: `@mcp-b/webmcp-polyfill` at exact 5.1.0 in the private `tests/map-page`, beside CLAUDE.md's allowance for the demo page; MCP-B 6.0.0 in `tests/mcpb6` in place of the beta (ADR 0047); and zod 4.6.5 in the private `packages/sim-page`, which CLAUDE.md lists. No new runtime dependency.

## Merge rules

Each wave runs in parallel worktrees, and one integrator merges it into `m6` at its end, runs `pnpm test`, `pnpm typecheck`, `pnpm lint` and `pnpm test:e2e`, and records the script-tag size below. No two workstreams in a wave edit one region: each workstream's brief names its files and the functions it owns in `hub.ts`, `core.ts` and `widget.ts`, a change to another's region is handed over, and a missing seam is stubbed in the workstream's own region and recorded here. New e2e helpers go in new files. Export lists in `index.ts` files and `package.json` scripts are append-only and resolved at merge, and `pnpm-lock.yaml` is regenerated with `pnpm install` at merge. Within a wave, workstreams finish in backlog order, 0038 to 0045.
