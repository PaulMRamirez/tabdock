# M4 checklist

Step 0, local mode (ADR 0022), run on 3 and 4 October 2026 in a Claude Code cloud session (Linux, Node 22.22, Claude Code 2.1.288). The sandbox runs as root and has no Windows or macOS, so another account's files are played through an injected `stat` and the other platforms through an injected platform and environment; what needs your own computer is left open below with steps. The later M4 workstreams add their items here as they land.

## Done in the sandbox

- [x] **Local mode by default.** No settings give local mode, explicit dev tokens or OAuth settings win, each setting that means nothing without a public URL is refused by name, production without auth settings refuses to start, and a `loopbackOnly` plugin under any name is refused with a public URL, in production or off loopback. `packages/relay/test/local-mode.test.ts` and `config.test.ts`.
- [x] **The owner token file.** A first start makes a 0700 directory and a 0600 file, the next start keeps it byte for byte, two racing starts end with one token, and every refusal (inside the checkout by `realpath`, another account's, readable by others, a symlink, not a regular or well-formed file, the Windows placement rule) names the path and the fix and never the contents. `packages/relay/test/local-token.test.ts`.
- [x] **This machine only.** `/mcp` and `/page` refuse `Forwarded` and every `X-Forwarded-*` header with 403 before the auth plugin answers, with no token, a wrong one or the right one; and a `TABDOCK_HOST` such as `localhost` whose lookup gives anything but loopback stops the relay before it listens. `packages/relay/test/local-mode.test.ts`.
- [x] **The banner and its command.** The printed POSIX line runs through `sh -c` against a stub `claude` from a path holding a space and quotes and passes exactly `Authorization: Bearer <token>`; the PowerShell line is checked as text. `pnpm relay` and `pnpm dev` run as children with a throwaway `TABDOCK_HOME`, a first start that cannot listen keeps its token and the next start still says how to replace an older entry, and no line on stdout or stderr holds the token, its digest or any 8 characters of it. `packages/relay/test/local-banner.test.ts`, `tests/e2e/test/local-mode.test.ts`.
- [x] **Claude Code (A4.4).** `pnpm --filter @tabdock/e2e check:claude-code:local` ran the line `pnpm relay` printed with Claude Code 2.1.288 in a throwaway HOME: `claude mcp list` showed `tabdock-local` connected, and rotation worked as the README describes (the old entry failed with HTTP 401, then `claude mcp remove` and the newly printed line connected again). It needs the installed CLI, so it is not in CI.

## For the owner

### 1. Local mode with Claude Code (A4.4, on your computer, about 10 minutes)

- [ ] In the checkout, move `.env` aside (`mv .env .env.m3`), since its settings win over local mode, and stop any relay from M1 to M3 still running on port 8787.
- [ ] Remove the M1-era entry from inside the checkout: `claude mcp remove --scope local tabdock`. It is fine if Claude Code says there is none.
- [ ] Run `pnpm relay`. It should say "Local mode", name `~/.config/tabdock/owner-token` on Linux or `~/Library/Application Support/Tabdock/owner-token` on macOS as "created just now", and print a `claude mcp add ... tabdock-local` line. `ls -l` on the file should show `-rw-------`, and `ls -ld` on its directory `drwx------`.
- [ ] Paste the printed line into another terminal. If Claude Code says `tabdock-local` already exists, run `claude mcp remove --scope user tabdock-local` and paste the line again. Then `claude mcp list` should show `tabdock-local` as Connected. Never run `claude mcp get tabdock-local`, which prints the token.
- [ ] Stop the relay and run `pnpm dev` instead, open the demo board link it prints, ask Claude Code to pair with the code in the widget, approve the request on the page, and ask for the board's view.
- [ ] Rotation: stop the relay, delete the `owner-token` file and start again. The banner should say "created just now", and `claude mcp list` should show the old entry failing with HTTP 401. Remove it, paste the new line, and check it shows Connected again.
- [ ] On Windows, if you have one: the same in PowerShell, where the banner prints a `Get-Content` form and the token lives in `%LOCALAPPDATA%\Tabdock`. In the file's Properties, on the Security tab, only you, SYSTEM and Administrators should be listed (ADR 0022). Note anything else you see.
