## For the owner, on a laptop (about ten minutes)

- [ ] **A0.2 interactively, as a person would use it.** In the repo run `pnpm install`, then `pnpm dev` and open `http://127.0.0.1:5173/?mcpb` in Chrome. In another terminal, from the repo root (this runs the relay copy pinned by the lockfile):

  ```sh
  claude mcp add webmcp-relay -- node "$PWD/tests/e2e/node_modules/@mcp-b/webmcp-local-relay/dist/cli.mjs" --widget-origin http://127.0.0.1:5173
  claude
  ```

  Ask Claude: "What tools does the demo board have? Add an item called hello at 100, 100 and highlight it." Expected: the item appears on the board with a yellow ring and the activity strip lists the calls. Note your Claude Code version and whether reloading the tab made Claude see the tools again without restarting. Remove the server afterwards with `claude mcp remove webmcp-relay`.

- [ ] **Watch the scripted demo.** `pnpm demo:m0 -- --headed` shows the board in a real window for 30 seconds after the calls (it downloads Playwright's Chromium on first run).
- [ ] **Native WebMCP, optional.** In Chrome 154 or later enable `chrome://flags/#enable-webmcp-testing`, relaunch, and open `http://127.0.0.1:5173/`. The status line should still say six tools are registered; the polyfill steps aside when the browser has its own `document.modelContext`. On Chrome 155 and later, expect MCP-B's 5.1.0 relay to fail every call (see `docs/notes/baseline.md`); that is the known string-versus-object change, not a demo bug.
