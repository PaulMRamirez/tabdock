# M2 checklist

Run on 2 and 3 October 2026 in a Claude Code cloud session (Linux, Node 22.22, headless Chromium 141 with the MCP-B polyfill, plus Chrome for Testing 154 and 156 for native WebMCP). What the sandbox could check is ticked with its evidence; what needs the owner's own laptop is left open with steps.

## Done in the sandbox

- [x] **A2.1** Two users and three client instances on one page, one of them on the 2025-era session leg and one on 2026-07-28; the page's roster lists both users and all three clients, and `list_pages` works for each. `tests/e2e/test/many-clients.test.ts` with the sim page, and the A2.1 test in `tests/e2e/specs/tabdock-relay.spec.ts` with the real widget.
- [x] **A2.2** The relay refuses an observer a write before the page hears of it, also when a demotion lands while the write waits in the queue; and the adapter refuses with `role_denied` when a stand-in relay skips the check and claims driver. `tests/e2e/test/role-checks.test.ts`, plus `Make observer stops the writes of a driver` in the browser spec.
- [x] **A2.3** Twenty concurrent writes from three clients run one at a time on the page, in the relay's arrival order (its `call queued` log lines), while reads run inside the first write. `tests/e2e/test/many-clients.test.ts` and `packages/relay/test/queue.test.ts`, which also keeps arrival order when argument checks differ in speed.
- [x] **A2.4** Revoke during a running write: the client gets `not_attached`, the page handler's `AbortSignal` fires (Chrome 156 profile), queued writes of that user end too, and the next call is refused. `tests/e2e/test/operator-controls.test.ts`, and by a real click on Revoke in the browser spec.
- [x] **A2.5** A consequential tool prompts on the page; Deny and silence both return `denied_by_operator`, and writes queued behind the prompt run after it. `tests/e2e/test/operator-controls.test.ts` and the M1 browser spec.
- [x] **Section 9 limits and the M2 decisions.** Users per page, calls per user per minute, queue depth, session caps, page-socket caps, idle expiry and argument checks each have tests in `packages/relay/test` (`limits`, `sessions`, `expiry`, `arguments`, `validate`, and `argument-budget`, `argument-checker` and `argument-main-thread` for ADR 0010, which prove a 2^n schema or a 1 MB array cannot stall the relay, and `tools-flood`, where twenty sockets from one address sending 1 MB tool lists cost the main loop at most about twice what plain frames of the same size cost, and get closed for their address's budget); session ownership (404 for another user's session id) and session ids kept out of logs are in `sessions.test.ts` and `logging.test.ts`.
- [x] **Claude Code.** `pnpm --filter @tabdock/e2e check:claude-code:m1` still passes on M2 with Claude Code 2.1.288, and `check:claude-code:m2` asserts that the page roster, the widget's roster row, the activity log and the widget's activity list all name `claude-code 2.1.288`. Claude Code speaks 2026-07-28, so the 2025-era session leg is covered by SDK clients only.
- [x] **Native WebMCP.** `tabdock-relay.spec.ts`, including the M2 tests, passes 13 of 13 on Chrome for Testing 154 (string input) and 156 (object input) through `CHROMIUM_EXECUTABLE`.
- [x] **One approval per page (ADR 0011).** A reload resumes, while another path of the same origin in the tab, even presenting the first page's token, pairs afresh. `tests/e2e/test/resume.test.ts`, `packages/relay/test/mcp.test.ts` and the adapter's core tests.
- [x] **Stable suite.** After the closing check, `pnpm test` passed 18 full runs out of 18, 8 of them beside three busy CPU loops; tests that read an argument check's outcome give it 2 s, so only the tests about the 50 ms budget depend on timing, and `tools-flood` is bounded against plain frames measured in the same run.
- [x] **Demo.** `pnpm demo:m2` passes from a clean `git archive` export after `pnpm install --frozen-lockfile`.

## For the owner, on a laptop (about twenty minutes)

- [ ] **Two people, one tab.** Follow "Try it by hand" in `docs/tour/02-many-clients.md` with two tokens and two Claude Code windows in different folders. Check that the roster names both clients, that the activity list keeps up, and that Revoke and Pause feel immediate. Note anything slow or unclear in the widget.
- [ ] **The widget on a small screen.** Open the demo page in Chrome's device toolbar at a phone size with two prompts and two roster rows showing. The panel scrolls there, which makes boxes wait again as they move; say whether that feels too slow to click.
