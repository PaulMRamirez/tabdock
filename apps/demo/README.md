# @tabdock/demo

A small canvas board whose state is easy to see, with six WebMCP tools: `get_view` and `list_items` read; `add_item`, `move_view` and `highlight_item` change the board; `clear_board` is consequential. People can pan by dragging and zoom with the wheel; every tool call is drawn at once and listed in the strip under the board.

`pnpm dev:demo` (from the repo root) serves it at `http://127.0.0.1:5173/` with live rebuilds; set `DEMO_PORT` in `.env` to move it. `pnpm dev` serves it beside a Tabdock relay. Adding `?relay=ws://127.0.0.1:8787/page` to the URL attaches the Tabdock adapter to that relay (only `ws:` and `wss:` URLs are accepted, an https copy takes `wss:` unless the relay is on the same machine, and the status line names the relay host), with `clear_board` listed in `policy.consequentialTools` because the MCP-B polyfill drops `consequentialHint`. `?invites=all` lets the operator mint Can control invites as well as Can watch ones and gives the board two driver seats, so a guest with control drives beside the operator's own client; `?invites=off` offers none, and without it the board offers Can watch invites only (ADR 0016). So the published copy (ADR 0021) is opened as `https://demo.<domain>/?relay=wss://relay.<domain>/page&invites=all`. The board never links to a relay inside a frame, in any build: a static host cannot forbid framing, and a framing site could dress the widget up to trick its operator into a click. `?e2e` is a test hook for the Playwright specs and demo scripts: it puts the adapter's control handle on `window.__tabdockDock`, which the adapter itself never does. Adding `?mcpb` loads MCP-B's local relay embed, which the M0 baseline uses; `?mcpb=9444` also picks the relay port. `?busy` is the M3 spike's CPU-busy variant for the Energy Saver run, since Energy Saver freezes only background tabs that use CPU: it spins in a worker for half of every 100 ms, `?busy=<1-100>` sets the share, and `&busyIn=main` spins in a timer on the page itself instead.

Files: `src/board.ts` holds the state, `src/tools.ts` defines the tools with zod schemas that double as their JSON Schemas, `src/render.ts` draws, `src/main.ts` installs the polyfill, registers the tools and attaches the adapter, `src/relay.ts` checks the `?relay` value, `src/policy.ts` reads `?invites` into the page's policy, and `scripts/server.ts` builds and serves with esbuild.
