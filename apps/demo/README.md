# @tabdock/demo

A small canvas board whose state is easy to see, with six WebMCP tools: `get_view` and `list_items` read; `add_item`, `move_view` and `highlight_item` change the board; `clear_board` is consequential. People can pan by dragging and zoom with the wheel; every tool call is drawn at once and listed in the strip under the board.

`pnpm dev:demo` (from the repo root) serves it at `http://127.0.0.1:5173/` with live rebuilds; set `DEMO_PORT` in `.env` to move it. `pnpm dev` serves it beside a Tabdock relay and prints a link with `?relay=` set.

The board dials only a relay its visitor chose (ADR 0029). With `?relay=ws://127.0.0.1:8787/page` it shows a bar reading `Connect to 127.0.0.1:8787` and attaches the Tabdock adapter only after a click the browser marks as the person's own, never a script's; without `?relay` it offers a Connect form that checks the URL by the same rules and goes to `?relay=`. The choice is remembered for that tab and that relay URL alone, so a reload reconnects without a second click. Only `ws:` and `wss:` URLs are accepted, with no user name, password, query or fragment, and an https copy takes `wss:` unless the relay is on the same machine; the status line names the relay host. `clear_board` is listed in `policy.consequentialTools` because the MCP-B polyfill drops `consequentialHint`. `?invites=all` lets the operator mint Can control invites as well as Can watch ones and gives the board two driver seats, so a guest with control drives beside the operator's own client; `?invites=off` offers none, and without it the board offers Can watch invites only (ADR 0016). `?confirm=client` sets `policy.confirmVia: 'client'`, so a member driver whose attachment no invite made confirms `clear_board` in their own MCP client rather than on the board, and the activity log says so; everyone else still gets the board's prompt (ADR 0026). The board never links to a relay inside a frame, and offers no bar or form there, in any build: a static host cannot forbid framing, and a framing site could dress the widget up to trick its operator into a click.

`?e2e` is a test hook for the Playwright specs and demo scripts, in the dev and test bundle only: it skips the click and puts the adapter's control handle on `window.__tabdockDock`, which the adapter itself never does. The static build defines the hook false and drops its code, which `tests/e2e/test/demo-static-build.test.ts` checks. Adding `?mcpb` loads MCP-B's local relay embed, which the M0 baseline uses; `?mcpb=9444` also picks the relay port. `?busy` is the M3 spike's CPU-busy variant for the Energy Saver run, since Energy Saver freezes only background tabs that use CPU: it spins in a worker for half of every 100 ms, `?busy=<1-100>` sets the share, and `&busyIn=main` spins in a timer on the page itself instead.

`node scripts/server.ts --build` writes the static build into `dist/`, as the Pages site uses it (`apps/site`, `pnpm site:build`): `index.html` gains a Content-Security-Policy meta (`default-src 'none'`, scripts from its own origin, the one inline style by its hash computed at build time, `connect-src wss: ws:`) and a no-referrer meta, and loads `./main.js` by a relative path, so a copy under `<user>.github.io/<repository>/` works too. The dev server sends its own headers instead and no meta policy.

Files: `src/board.ts` holds the state, `src/tools.ts` defines the tools with zod schemas that double as their JSON Schemas, `src/render.ts` draws, `src/main.ts` installs the polyfill, registers the tools and attaches the adapter once the visitor chooses, `src/connect.ts` draws the Connect bar and form and remembers the choice, `src/relay.ts` checks a relay URL, `src/policy.ts` reads `?invites` and `?confirm` into the page's policy, and `scripts/server.ts` builds and serves with esbuild.
