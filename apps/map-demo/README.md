# @tabdock/map-demo

The map demo (ADR 0050) shows people what a page can offer an MCP client: Earth as a flat map and a globe, drawn on a plain canvas from Natural Earth's public-domain data with no map library, whose tools Claude or any MCP client uses to move the view, take a short tour, capture what it sees and follow the page's state. It is the map profile from `@tabdock/sim-page/map` (ADR 0038, [Map and globe pages](../../docs/guide/16-map-pages.md)) in a presentable page, built into the Pages site at `/map/` beside the demo board at `/`. It is private and never published to npm.

It is never CI's fixture. `tests/map-page`, the canvas page of the Moon that the Playwright specs, the copyable check in `tests/ci-check` and `pnpm demo:m6` rest on, stays as it is, and this app imports nothing from it, so the demo can change how it looks without moving the fixture, its walker's expectations or the check. The renderer, the capture's fit loop and the gestures here follow the fixture's without sharing its code, so a fix to one may be owed to the other.

## What it shows

The page opens on the globe over the Atlantic. Its one walkthrough, "A short tour of Earth", has six stops, each with one fact checked against a source on 13 October 2026 and rounded with "about": Earth from afar on the globe (water covers about 71 percent of its surface), the Caspian Sea on the flat map (the largest inland body of water, a gap in the land in this data), Lake Baikal on the globe (the deepest lake), the Great Lakes on the flat map (Lake Superior, counted alone, the largest freshwater lake by area), Lake Victoria on the flat map (Africa's largest lake, which the Victoria Nile leaves) and Madagascar on the globe (the fourth largest island). Five layers can be shown or hidden: land, lakes, a 30 degree graticule, observation outlines and names. Its 26 features are the data's 24 lakes, the Caspian Sea and Madagascar, and its three observations outline the Caspian, Baikal and the Great Lakes from the data itself, each marked as an outline, not a photograph, and credited to Natural Earth.

It registers fourteen tools: the profile's core (`get_view` and `set_view`) and its capture, layers, features, walkthroughs and observations groups, with no clock group since this world has no clock, beside `edit_stop` and `reset_edits`. It attaches under `MAP_PAGE_POLICY` with `capture_view` as its image tool, so `reset_edits` alone asks the operator, and proposals stay off. `capture_view` draws the map again on a canvas of its own at the world's fixed 960 by 540 viewport, never the tab, whose widget shows the pairing code, and fits the PNG or JPEG under the relay's image cap; one view gives the same bytes each time. Once linked, the page publishes its view, stop and observation as page state on each change (a drag, a wheel step or a button press is one change) and never the same state twice, so a client can follow it with `wait_for_page_state`. Under the map, buttons zoom, switch between the flat map and the globe and step through the tour, since a phone has no wheel; a line names the view; the tour panel shows the current stop's text, edits included, as plain text; and a strip lists recent calls by tool name and outcome only, never their arguments.

## Run it from a clone

```sh
pnpm relay          # one terminal: local mode, for Claude Code on this computer
pnpm dev:map-demo   # another: the page on http://127.0.0.1:5175/
```

`pnpm dev:map-demo` serves the page on port 5175 (or `MAP_DEMO_PORT`, or `--port`), rebuilding as you edit, with the static build's own `index.html` and policy, and prints a link with `?relay=` set for `pnpm relay` on `TABDOCK_PORT` or 8787. The relay's development default admits a page on any loopback origin, so nothing needs setting. Add the relay to Claude Code with the line `pnpm relay` printed, open the link and click Connect on the bar (its button takes a click once it has held still for half a second); then ask Claude Code to pair with the code the widget shows, and click Allow as driver. The page's links to the board, the tour and the guide work only on the published site.

`pnpm --filter @tabdock/map-demo build` writes the static build into `dist/`: the page, carrying the board's meta policy without `worker-src` and a no-referrer meta, its script minified, and the script's source map. `scripts/server.ts` exports `buildMapDemo()`, which writes the same build into any directory, for the Pages site's build to put at `/map/`. ADR 0050's budget holds the script to 800,000 bytes (200,000 gzipped) and the page to 16,000, which `test/server.test.ts` checks against the build, and the vendored data to 24,000, which `test/vendor.test.ts` checks.

## Connect your own Claude

From the published page, with a relay on your own computer:

1. Run a relay that admits the site's origin, which the page shows under its Connect form. For Claude Code on your own computer, local mode does: in a clone, `TABDOCK_ALLOWED_ORIGINS=<the site's origin> pnpm relay`, then add the relay to Claude Code with the line it prints. The list replaces the loopback default, so name `http://127.0.0.1:5175` in it too if you also want the dev server.
2. Open the map, type `ws://127.0.0.1:8787/page` in the Connect form and click Connect. An https page may reach a `ws:` relay only on loopback, and your browser may ask first whether the public page may reach your own machine; allow it.
3. Ask Claude Code to pair with the code the widget shows, click Allow as driver, and try one of the page's prompts, such as "Take this page's tour and capture each stop."

Claude on the web, the desktop app and the phone reach a connector from the cloud, so a loopback relay cannot serve them: run public URL mode through a tunnel (`pnpm dev:public`) with the site's origin in `TABDOCK_ALLOWED_ORIGINS` and the map open in a browser on the relay's machine, which dials `ws://127.0.0.1:8787/page` as above, or a hosted relay that lists the origin, which the page dials at its `wss:` URL. [Run a relay](../../docs/guide/07-run-a-relay.md) and [Connect clients](../../docs/guide/05-connect-clients.md) have the steps.

The page dials only a relay its visitor chose, by the board's rules (ADR 0029): `?relay=` shows a Connect bar that takes only a person's own click once its button has held still, and without it the page offers the Connect form. The choice is remembered for the tab under `tabdock-map-demo:connect:`, apart from the board's, so a relay chosen on the board never connects the map. It reads no policy from its link, has no test hook in any build and never links inside a frame.

## Files

`src/main.ts` wires the polyfill, the world, the tools, the canvas and the link; `src/earth.ts` holds the world, its tour and its outlines; `src/decode.ts` reads the vendored data; `src/projection.ts` holds the flat map's copies and the globe's limb; `src/draw.ts` draws a scene, `src/capture.ts` fits `capture_view`'s picture under the relay's cap, `src/gestures.ts` turns drags, the wheel and the buttons into one world write each, `src/publish.ts` sends the page state, `src/panel.ts` writes the view line, the tour panel and the call strip as text, `src/connect.ts` draws the Connect bar and form, using `@tabdock/demo/relay` and `@tabdock/demo/arming`, and `src/webmcp.ts` declares the slice of WebMCP the page uses. Unit tests sit beside the modules; `test/` holds those that read files or start the server. `tests/e2e/specs/map-demo.spec.ts` (run by `pnpm test:e2e`) links the static build in Chromium as a visitor would, with a click on the Connect bar and Allow in the widget, and `pnpm site:build` reads `/map/` back from disk and stops unless it holds only the page, its script and the source map under its policy (`apps/site/lib/checks.ts`).

## The data

The geography is Natural Earth's 1:110 million land and lakes at tag v5.1.2, from [github.com/nvkelso/natural-earth-vector](https://github.com/nvkelso/natural-earth-vector). Natural Earth's terms of use place all its data in the public domain and ask no credit; the page and `NOTICE` give the credit the terms suggest anyway, "Made with Natural Earth. Free vector and raster map data @ naturalearthdata.com." Lake names are Natural Earth's own.

`src/data/natural-earth-110m.ts` is generated by `scripts/vendor-natural-earth.ts` and is never edited by hand. `pnpm --filter @tabdock/map-demo vendor` runs it, by hand: it fetches `ne_110m_land.geojson` and `ne_110m_lakes.geojson` at the tag, stops unless each file's SHA-256 is the one it pins, rounds every position to 0.1 degree, winds rings as RFC 7946 asks and writes them in the compact form `src/decode.ts` reads. `node apps/map-demo/scripts/vendor-natural-earth.ts --from <dir>`, from the root, reads two files you already have instead. The same files give the same bytes, so a rerun shows no diff. No CI job runs it, and the page fetches no map data: the geography is in its script.
