# @tabdock/site

The GitHub Pages site (ADRs 0029, 0035 and 0050): the demo board's static build at `/`, the map demo's at `/map/`, the explainers of `docs/tour` at `/tour/`, one per milestone, and the user guide of `docs/guide` at `/guide/`, its `README.md` the guide's index. It is a private package and never reaches npm.

`pnpm site:build` from the repository root installs this directory from its own lockfile (`pnpm --dir apps/site install --frozen-lockfile --ignore-workspace`), runs `check` (a typecheck and the tests in `lib/` with `node --test`), then runs `scripts/build.ts`, which writes everything into `apps/site/dist`. The site keeps its own `pnpm-lock.yaml` and its own `pnpm-workspace.yaml` outside the root workspace, so `marked`, `mermaid` and `playwright-core` never enter the workspace's tree and Dependabot updates the site's lockfile apart. It needs the workspace installed, for the two demos' builds, and Playwright's Chromium, which `pnpm --filter @tabdock/e2e exec playwright install chromium` fetches; `CHROMIUM_EXECUTABLE` points it at another Chromium.

## What the build does

`build.ts` first runs the demo's own static build (`buildDemo` in `apps/demo/scripts/server.ts`) into `dist/`, then the map demo's (`buildMapDemo` in `apps/map-demo/scripts/server.ts`) into `dist/map/`. It then renders each Markdown page of the tour and the guide with `marked` (`markdown.ts`), taking the page list from each directory, so a new page needs no change here, and refuses a file name that is not lower case, digits and hyphens. `links.ts` turns a link to a page of either collection into that page's `.html`, stops the build on a link to a page that does not exist, keeps a link into a collection's `img/` on the site, and turns any other repository path into a GitHub link at the commit built, whose address `repo.ts` reads from Actions or from git at build time, never from a committed file. The guide's index must link every guide page, or the build stops naming the ones it misses.

Each Mermaid block is drawn to an SVG at build time (`diagrams.ts`), in Playwright's Chromium with every request and socket refused, so no published page needs a script; the README's diagrams are drawn too, though not published, so one that would not draw on GitHub stops the build. Raster images in a collection's `img/` are copied; an SVG of its own is refused, since it could carry script. `page.ts` wraps each page in its HTML, under the site's policy and a no-referrer meta, with one stylesheet, `assets/tour.css`.

Last, `checks.ts` reads back every file written to `dist/tour` and `dist/guide`, as Pages will serve it, and stops on any page or diagram that holds a script, an event handler attribute or an outside URL, lacks the policy, or is a kind of file the site does not ship. The tour and the guide share the demo's origin, where the adapter keeps its records, so both are held to the same rules word for word.

The site's two pages with script, the board at `/` and the map demo at `/map/`, are read back last by `scriptedDirProblems` in `checks.ts`, against the board's static rules restated there rather than taken from the build: a Content-Security-Policy meta first in the head, exactly the board's policy with the hash of the page's one inline style (and `worker-src blob:` for the board's `?busy` worker alone), the no-referrer meta, one module script, its own bundle loaded by a relative path, no inline script, event handler, style attribute, frame, form, base or link, and no URL with a scheme or from the host's root.

Beside each page only its bundle and that bundle's source map may sit (with the tour, the guide and the map beside the board); no bundle may hold a test hook; every link must lead to a file the site holds; the board must link `map/`, so a visitor finds it; and the map demo stays within ADR 0050's budget of 16,000 bytes of HTML and 800,000 bytes of script, 200,000 gzipped. Every tour and guide page's header links the map demo too.

`.github/workflows/pages.yml` publishes the result when dispatched on `main`; until the owner first runs it, nothing is published and the board runs with `pnpm dev`. Serve `apps/site/dist` with any static server to read it as Pages would. The root's lint, typecheck and unit tests leave this directory out, since a clean clone cannot resolve its packages, and CI runs `pnpm site:build` after it installs Chromium.
