# @tabdock/site

The GitHub Pages site (ADRs 0029 and 0035): the demo board's static build at `/`, the explainers of `docs/tour` at `/tour/`, one per milestone, and the user guide of `docs/guide` at `/guide/`, its `README.md` the guide's index. It is a private package and never reaches npm.

`pnpm site:build` from the repository root installs this directory from its own lockfile (`pnpm --dir apps/site install --frozen-lockfile --ignore-workspace`), runs `check` (a typecheck and the tests in `lib/` with `node --test`), then runs `scripts/build.ts`, which writes everything into `apps/site/dist`. The site keeps its own `pnpm-lock.yaml` and its own `pnpm-workspace.yaml` outside the root workspace, so `marked`, `mermaid` and `playwright-core` never enter the workspace's tree and Dependabot updates the site's lockfile apart. It needs the workspace installed, for the demo's build, and Playwright's Chromium, which `pnpm --filter @tabdock/e2e exec playwright install chromium` fetches; `CHROMIUM_EXECUTABLE` points it at another Chromium.

## What the build does

`build.ts` first runs the demo's own static build (`buildDemo` in `apps/demo/scripts/server.ts`) into `dist/` and stops unless its `index.html` carries its Content-Security-Policy meta. It then renders each Markdown page of the tour and the guide with `marked` (`markdown.ts`), taking the page list from each directory, so a new page needs no change here, and refuses a file name that is not lower case, digits and hyphens. `links.ts` turns a link to a page of either collection into that page's `.html`, stops the build on a link to a page that does not exist, keeps a link into a collection's `img/` on the site, and turns any other repository path into a GitHub link at the commit built, whose address `repo.ts` reads from Actions or from git at build time, never from a committed file. The guide's index must link every guide page, or the build stops naming the ones it misses.

Each Mermaid block is drawn to an SVG at build time (`diagrams.ts`), in Playwright's Chromium with every request and socket refused, so no published page needs a script; the README's diagrams are drawn too, though not published, so one that would not draw on GitHub stops the build. Raster images in a collection's `img/` are copied; an SVG of its own is refused, since it could carry script. `page.ts` wraps each page in its HTML, under the site's policy and a no-referrer meta, with one stylesheet, `assets/tour.css`.

Last, `checks.ts` reads back every file written to `dist/tour` and `dist/guide`, as Pages will serve it, and stops on any page or diagram that holds a script, an event handler attribute or an outside URL, lacks the policy, or is a kind of file the site does not ship. The tour and the guide share the demo's origin, where the adapter keeps its records, so both are held to the same rules word for word.

`.github/workflows/pages.yml` publishes the result when dispatched on `main`; until the owner first runs it, nothing is published and the board runs with `pnpm dev`. Serve `apps/site/dist` with any static server to read it as Pages would. The root's lint, typecheck and unit tests leave this directory out, since a clean clone cannot resolve its packages, and CI runs `pnpm site:build` after it installs Chromium.
