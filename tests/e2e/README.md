# @tabdock/e2e

End-to-end tests and milestone demos. `src/harness.ts` starts the demo page in Chromium, MCP-B's local relay as a stdio MCP server, and an MCP client from the official SDK (M0). `src/tabdock-harness.ts` starts the Tabdock relay with throwaway dev tokens beside the demo page, opens the page with `?relay` and the `?e2e` test hook, connects MCP clients with a bearer header, and clicks inside the adapter's closed shadow root through the DevTools protocol (M1).

`test/*.test.ts` run in `pnpm test` without a browser: the relay, sim pages running the real adapter core, and MCP clients in one process, covering A1.1, A1.3 and A1.4 on the default sim profile (Chrome 156), with `runtimes.test.ts` running the pair, list and call path on every profile the sim page plays (MCP-B polyfill 5.1, Chrome 154, Chrome 156). `pnpm test:e2e` (from the root) runs the Playwright specs in `specs/`: the M0 baseline through MCP-B, and the real adapter on the demo page against the Tabdock relay. `pnpm demo:m0` and `pnpm demo:m1` narrate one session each; add `-- --headed` to watch or `-- --screenshot` to refresh `docs/tour/img/m0-board.png` or `m1-board.png`. `pnpm --filter @tabdock/e2e baseline` re-measures the WebMCP runtime into `docs/notes/baseline.raw*.json`. `check:claude-code` (A0.2) and `check:claude-code:m1` (A1.2) run the real Claude Code CLI; it must be installed and signed in, and each spends a few model calls.

Browsers: the harness and the Playwright global setup download Playwright's Chromium on first use. Set `CHROMIUM_EXECUTABLE` to use another Chrome, for example one with native WebMCP; the harness always passes `--enable-features=WebMCPTesting`.
